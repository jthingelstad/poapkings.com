# poapkings.com

Static multi-page site for the POAP KINGS Clash Royale clan, built with Eleventy and deployed to GitHub Pages.

## Read first

- Preserve unrelated work in a dirty checkout.
- Do not hand-edit `_site/`; it is generated by Eleventy.
- The Clash Royale API key is host-local and IP restricted. Never print or commit it.
- `OPERATOR.md` governs the daily data-only refresh workflow and has a deliberately narrow write boundary.

## Build and preview

Use Node 24, matching `.node-version` and `package.json`.

```bash
npm ci
npm run build
npm start
```

The local server is `http://localhost:8080`. Pushing `main` triggers `.github/workflows/deploy.yml`, which builds and publishes `_site/` through GitHub Pages.

## Rendering conventions

- Pages using the shared shell set `layout: base.njk` and provide `title`, `description`, and an optional `navActive` value.
- Use macros from `components.njk` for repeated presentation patterns.
- Use named CSS classes instead of inline style strings. Dynamic chart colors use the shared `pk-series--*` classes and CSS custom properties.
- Player tags are normalized with the `playerTag` filter and rendered with `playerTagLink`; player URLs use `https://royaleapi.com/player/TAG` without `#`.
- JSON embedded in `<script type="application/json">` must use `jsonForScript | safe`, never `dump | safe`.
- `gamify.js` is bundled by esbuild. PixiJS must remain a dynamic import that loads only when the star count resolves or a star interaction needs particles.
- Static CSS/JS references use the `bust` filter for content-hash query strings.

## Data refresh

Run locally:

```bash
npm run update-roster
```

The updater reads `CR_API_KEY` from the shell or `../elixir-bot/.env`, fetches clan, player-profile, and river-race facts, and updates only when generated data changes. It owns:

- `src/_data/clan.json`
- `src/_data/roster.json`
- `src/_data/clanInsights.json`
- `src/_data/clanTrends.json`
- `src/_data/rosterExplorer.json`
- `src/_data/warHistory.json`
- `data/clash-royale.sqlite`

Use `npm --silent run update-roster -- --dry-run --exit-code` for a non-writing probe. Exit `0` means no change; exit `2` means data would change. Use `npm run backfill-data` only for an explicitly requested historical import, never in the daily operator flow.
